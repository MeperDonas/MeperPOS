## Risk and impact up front (required by S3)

| Change | Risk | Impact on cache/functionality |
| --- | --- | --- |
| CSP: drop `unsafe-eval` in production | Low. Next only needs it for dev HMR/`eval`-based source maps. If a proven dependency needs it, it stays with a documented justification. | None on the CDN cache (headers do not change the render mode). |
| CSP: remove `http://localhost:3001`/`127.0.0.1` from `connect-src` | None for production; dev uses `NODE_ENV=development`. | None. Removes a dev-config leak into the production policy. |
| CSP: add `object-src 'none'`, `upgrade-insecure-requests`, `worker-src 'self'`, `manifest-src 'self'` | Low. | None. |
| CSP: keep `'unsafe-inline'` in `script-src` (phase 1) | Accepted: Observatory keeps the −20 (grade stays B+). | None: `/login` keeps its prerender and `x-vercel-cache: HIT`. |
| CSP hash strategy (evaluated, not applied) | A hash list must be recomputed on every build; Next's RSC bootstrap payload is per-build and per-route, so hashes are brittle and can silently break hydration. | Nonce is the supported path, and it forces dynamic rendering on every route, which is exactly what S3 forbids in phase 1. |
| `Content-Security-Policy-Report-Only` variant (opt-in, default off) | None: it never blocks. | None; used to collect violations before enforcing a stricter phase 2. |
| `Cache-Control: no-store` on auth/sensitive responses | Low; it only forbids caching. Applied to API auth endpoints and to the authenticated app routes, never to `/login`, `/register` or `/_next/*`, so the public CDN cache is preserved. | Public pages keep `HIT`; authenticated pages are already per-user. |
| Exports formula neutralization | Low. Prepends `'` to cell values starting with `=`, `+`, `-`, `@`, tab or CR. | Export content is textually prefixed; opened in Excel/Sheets the cell shows the original text. |
| `trust proxy` + per-route throttling | Medium: it changes `req.ip` and therefore rate limiting and AuditLog IPs. Must match the real Railway hop topology (S4.2). | Login/register/refresh get tighter limits; verified against the real path. |
| Shared throttler storage (Redis, env-gated) | Medium: new dependency and a new env var. Inert unless `REDIS_URL` is set, so deploy is unchanged until the user activates it. | `/api/health` unaffected. Multi-replica counting becomes real instead of per-replica. |
| `next` 16.1.3 → 16.4.2 (+ matching `eslint-config-next`) | Medium: minor upgrade, closes a critical Image Optimizer DoS from `npm audit`. | Requires a rebuild and redeploy; `/login`, hydration, `next/image` with the Cloudinary loader, lint, typecheck and tests are all re-verified (S5). |

## Redis: cost and single-replica alternative (required by S4)

- **Replica count: NOT verifiable from this machine.** There is no `railway` CLI installed and no Railway API token, so the real replica count must be confirmed by the user in the Railway dashboard (Service → Settings → replicas, or `Deployments` scaling). Everything below is written so that it is correct for N ≥ 1.
- **Cost of the shared store**: one Railway Redis service on private networking. Typical Railway usage-based pricing for a small Redis (256 MB–1 GB) lands around US$5/month plus a few dollars of egress; a private `redis://` URL keeps it off the public internet, and a password (`REDIS_URL` with credentials) is required by S4.6.
- **Single-replica alternative (cheaper, zero new infra)**: keep in-memory storage but pin the API to exactly one replica. Then the counters are honest again, at the cost of losing horizontal scaling and of a cold-start reset. This is the recommended option while traffic is low; the Redis adapter shipped in T7 stays inert until `REDIS_URL` exists.
- **Unavailability behavior**: without `REDIS_URL` the adapter uses in-memory storage and logs a single startup warning; if Redis is configured but unreachable, the app must not crash and must not silently stop throttling — it falls back to in-memory and logs a prominent error (documented, tested).
